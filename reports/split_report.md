# Split report

Generated by `src/dataset/check_splits.py` from `splits/manifest.csv`.

## 1. How the split was made

- All 54,304 images from the shipped `train/` and `val/` folders were pooled (the shipped split was ignored; it has no test set and leaked, see below).
- One image was excluded: the `.png` pepper-fruit photo, which is not a lab leaf image (see `reports/audit.md`). The one `.jpeg` file is a normal leaf and is kept.
- Byte-identical images and near-duplicates (same class, very similar thumbnails; `reports/duplicates.md`, `reports/groups.md`) share a `group_id`. 73 groups have 2+ images, covering 177 images; the largest has 10. Every other image is its own group.
- Stratified, grouped 10-fold split (`StratifiedGroupKFold`, seed 42): one fold is test, one is val, eight are train. Whole groups stay together.
- `path` is relative to the `PlantVillage` data folder. The `train/` or `val/` at the start of a path is only where the file physically sits, not its split.

## 5. Notes and limits

- **Small test sets.** Smallest classes: `Potato___healthy` (train 121, val 16, test 15), `Apple___Cedar_apple_rust` (train 221, val 27, test 27), `Peach___healthy` (train 288, val 36, test 36), `Raspberry___healthy` (train 297, val 37, test 37), `Tomato___Tomato_mosaic_virus` (train 299, val 37, test 37). The smallest test set has 15 images, so per-class scores for these classes are noisy; a single error moves them by several points.

- **The shipped split leaked.** 29 groups had images in both the shipped `train/` and `val/` folders (byte-identical files and near-duplicates). This split has none.

- **Limit of duplicate detection.** Grouping uses image similarity. The same leaf photographed from a clearly different angle is not reliably detected, so some leaf-level similarity across splits may remain. Look-alike leaves can also be grouped together; that only makes the split slightly more conservative.

- **Image size.** All images are 256x256. MobileViT-XS (256) uses them as they are; MobileNetV2 (224) needs a resize, so FLOPs and latency reflect architecture and input size together.
